# Agents authenticate with a bearer credential over ordinary TLS

Supersedes [0005](0005-agent-mtls-terminated-in-front-of-the-platform.md).

An Agent proves who it is with a credential the platform made for it at Agent Registration, sent as `Authorization: Bearer agk_...` on every call after registering. The platform stores only its SHA-256, the Agent keeps the credential in its state directory (readable only by its service account), and the Agent replaces it with a new one once a third of its life is left (30 days). The old one stays accepted until the new one is first used, so an Agent that never received the response can try again. Revoking an Agent ends its credential at once. The platform serves TLS itself (`TLS_CERT_FILE` and `TLS_KEY_FILE`) or sits behind any ordinary TLS terminator, and an Agent talks to it only over HTTPS (plain HTTP is accepted only for a loopback address, so that development needs no certificate).

We chose this over the mTLS design of ADR 0005. Bun's HTTP server enforces a client certificate in the handshake but does not tell the request handler which one it was, so mTLS needed a terminator in front of the platform that passed the verified certificate in a header. That header is trusted only if the platform's port is unreachable except through the terminator, so it needed a shared secret, a second verification in the platform, and a gateway to run an Agent on a laptop; and mTLS fails through the TLS-inspecting egress proxies that are common where Agents run, which a bearer credential does not. What the platform needs from an Agent's authentication is that it never holds a secret that can impersonate the Agent (it holds a hash), that it can end it at once, and that it can be replaced; a credential does all three. We also chose it over signing every request with a key the Agent keeps, which holds no secret in transit but adds replay protection and body hashing for little practical gain: an attacker who can read the Agent's state directory has either.

The Agent no longer has a CSR or a key for its own identity (ADR 0002 is about the keys of Managed Certificates, which is unchanged: the platform still never holds one). The Agent identity CA, its table and the `/api/agent/identity-ca` route are gone.

Consequences: a credential is a secret, so it must not be logged, and the platform must be reached over TLS in production. An Agent that is away longer than its credential lasts (30 days) cannot rotate and registers again with a new token. Agents registered under ADR 0005 have no credential and register again.
