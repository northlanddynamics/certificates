# 03: Secrets and the Let's Encrypt ACME account

**What to build:** An Organization Administrator can register their Organization's ACME account with Let's Encrypt, choosing staging or production. The account key and any other secrets are stored with envelope encryption: a data key per Organization, wrapped by a pluggable KMS (a local key for development; AWS KMS and Azure Key Vault adapters behind the same interface). Secrets are write-only.

**Blocked by:** 01 (Walking skeleton)

**Status:** done

- [x] An Organization Administrator can create an ACME account against Let's Encrypt staging or production (Pebble in tests).
- [x] Staging is the default for a new Organization.
- [x] No API, including for Organization Administrators or an impersonating Platform Operator, returns a secret's value; secrets can be replaced or tested only.
- [x] Each Organization's secrets are encrypted under its own data key.
- [x] The KMS is pluggable, with a local implementation used in development and tests.
- [x] Account creation and secret replacement are audited without the secret's value.

## Comments

Implemented on `main`; typecheck and the full Seam A suite pass against Postgres and Pebble in Docker Compose (`docker compose up -d --wait`).

- Routes: `GET`/`POST /api/organizations/{orgId}/acme-accounts`, `PUT .../{accountId}/key`, `POST .../{accountId}/test`; permission `acmeAccount` (Organization Administrator only). The account key is generated by the platform and never returned.
- "Staging is the default" is read as the default of the create request's `environment`; an Organization has at most one account per environment. Creating an Organization creates no account.
- "Replace" means the administrator supplies a PEM key that the CA already accepts for the account (for example after a rollover at the CA); it is checked against the CA before it is stored.
- Not built: the AWS KMS and Azure Key Vault adapters (the `Kms` interface and the local implementation are; nothing yet selects a KMS besides `LOCAL_KMS_KEY`), and a web UI. Neither is an acceptance criterion.
- Known: two concurrent creations for the same environment can leave an unused account at the CA (the loser gets a 409), which Let's Encrypt counts against its account rate limit.
